**Simple Energy HMI Dashboard**

A landscape Android HMI dashboard prototype built with Kotlin and
Jetpack Compose. It displays simulated vehicle speed, motor status, and
kill-switch status, with a dashboard layout inspired by the Simple
Energy reference image supplied with the assignment.
Note: This project uses simulated vehicle data. It is a
demonstration UI and is not connected to a real vehicle, ECU, CAN bus,
sensors, or production telemetry.

**Features**
- Landscape dashboard layout inspired by the supplied HMI reference.
- Central digital speed display and curved speed visualisation.
- Vehicle motor ON/OFF indicator.
- Kill-switch ACTIVE/INACTIVE indicator.
- Five vehicle states: Parked, Ready, Riding, Accelerating, and Motor
  disabled.
- Automatic UI updates using Kotlin Coroutines, Flow, and StateFlow.
- Hilt dependency injection.
- MVVM and separation between presentation, domain, and data.
- Validation for negative and non-finite speed values.
- Handling for missing, stale, and failed vehicle-data streams.
- Visual representations of the 36 reference features. Features
  without a backing data source are placeholders, not live telemetry.

Jetpack Compose Dashboard
The provider emits VehicleData. The repository exposes the stream, the
use case provides the domain entry point, and the ViewModel collects it
and publishes UI state through StateFlow. Compose collects that state
lifecycle-aware and recomposes when values change.
Simulated vehicle states
State                              Speed Motor   Kill switch
Parked                            0 km/h OFF     Inactive
Ready                             0 km/h ON      Inactive
Riding             Progressively changes ON      Inactive
Accelerating       Progressively changes ON      Inactive
Motor disabled                    0 km/h OFF     Active

The simulation cycles continuously. Update intervals are configured in
SimulatedVehicleDataProvider.kt. Motor state and speed are separate
properties; motor OFF must not be used as a general rule to infer that a
moving vehicle has instantly stopped.
Build and run
Requirements
- Android Studio compatible with AGP 9.5.0.
- JDK 17.
- Android SDK Platform 37.
- Android emulator or device.
- Landscape emulator profile recommended.
  Android Studio
1. Clone this repository.
2. Open the project in Android Studio.
3. Select JDK 17 for Gradle.
4. Allow Gradle sync to finish.
5. Start an emulator configured in landscape orientation.
6. Select the app run configuration and press Run.
   Command line
   macOS/Linux:
   ./gradlew clean
   ./gradlew assembleDebug
   ./gradlew installDebug
   Windows:
   gradlew.bat clean
   gradlew.bat assembleDebug
   gradlew.bat installDebug
   The debug APK is normally generated at:
   app/build/outputs/apk/debug/app-debug.apk
   Run unit tests
   macOS/Linux:
   ./gradlew testDebugUnitTest
   Windows:
   gradlew.bat testDebugUnitTest
   Tests should cover vehicle-data validation and ViewModel state updates,
   including stale or missing data. Update tests whenever simulation timing
   or state logic changes.
   Edge cases
- Negative speed values are normalized to 0 km/h with a warning.
- NaN and infinite speed values are normalized to 0 km/h with a
  warning.
- Missing initial data is represented as unavailable/loading rather
  than fabricated live data.
- Stale data is flagged when no update arrives within the configured
  timeout.
- Data-stream errors are represented as a connection/error state.
  Dashboard reference and placeholders
  The dashboard UI is inspired by the reference image in the assignment.
  The 36 visual elements are represented for layout purposes. Unless
  explicitly connected to a data source, range, battery SOC, navigation,
  TPMS, cruise control, notifications, and other vehicle indicators are
  illustrative placeholders.

The assignment-required speed, motor status, and kill-switch status are
driven by the simulated vehicle stream.
Assumptions and limitations
- No physical vehicle, hardware interface, CAN bus, ECU, Bluetooth
  device, or sensor integration is included.
- Vehicle values are generated by a local simulation.
- Some dashboard indicators use static demonstration values.
- The speedometer visual scale is a UI choice, not a calibrated
  instrument.
- This prototype must not be used for actual vehicle operation or
  safety decisions.
